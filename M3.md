### T3.1 — Chunking module (three schemes, no eval yet)
- **Objective:** implement whole-review, fixed-token (128/256), and sentence-window chunking as pure, swappable functions — no verdict yet on which is best.
- **Files to create:**
  - `src/cragb/retrieval/chunking.py`
  - `configs/chunking.yaml`
  - `tests/test_chunking.py`
- **Python packages:** none new (stdlib `re`, existing `pandas`). Do not pull in `nltk`/`spacy` for sentence splitting — a regex splitter is enough here.
- **Expected outputs:** each chunker takes `corpus_v1` (+ `text_col`) and returns a chunk-level `DataFrame` with `[chunk_id, parent_doc_id, text]`. For whole-review, `chunk_id == parent_doc_id`. Config exposes `scheme`, `fixed_token_size ∈ {128,256}`, `sentence_window_size`.
- **Validation checks:** chunk ids unique per scheme; every chunk traces to a valid `parent_doc_id`; fixed-token chunks respect the token cap; whole-review chunk count == corpus row count; no chunk has empty text.
- **How I verify it worked:** `pytest tests/test_chunking.py -v` all green; manually inspect 2–3 chunks per scheme in a scratch script.
- **Git commit:** `T3.1: chunking module (whole-review / fixed-token / sentence-window)`
- **Mid-progress report use:** infrastructure only — not directly cited, but required for the chunking table (T3.4).

### T3.2 — Retrieval metrics module (Recall@k, Hit@k, nDCG@k, MRR)
- **Objective:** correct, unit-tested implementations of all four G1 metrics — PLAN.md flags a wrong Recall implementation as invalidating everything downstream, so this is its own task before any real eval runs.
- **Files to create:**
  - `src/cragb/eval/__init__.py`, `src/cragb/eval/metrics_retrieval.py`

- **Python packages:** `numpy` only (already in `environment.yml`).
- **Expected outputs:** functions `recall_at_k`, `hit_at_k`, `ndcg_at_k`, `mrr` — each `(ranked_doc_ids: list[str], relevant_ids: set[str], k: int) -> float`, plus a `score_all(ranked, relevant, k_values)` convenience wrapper.
- **Validation checks:** hand-computed toy cases (relevant doc at rank 1 → Recall@1=1.0, MRR=1.0; relevant doc absent → all metrics 0; nDCG matches a manually computed value); Recall is monotonically non-decreasing in `k`.
- **How I verify it worked:** `pytest tests/test_metrics_retrieval.py -v`; spot-check one metric against a manual calculation in a scratch notebook cell.
- **Git commit:** `T3.2: retrieval metrics (Recall/Hit/nDCG/MRR) + unit tests`

### T3.3 — Bootstrap CI + significance testing module
- **Objective:** paired bootstrap 95% CI and a paired significance test (Wilcoxon signed-rank) over the shared question set, per PLAN.md §8's cross-cutting rigor requirement.
- **Files to create:**
  - `src/cragb/eval/bootstrap.py`
  - `tests/test_bootstrap.py`
- **Python packages:** **new** — `scipy` (not currently in `environment.yml`; add it there in this task, conda-forge channel).
- **Expected outputs:** `bootstrap_ci(scores: list[float], n_boot=10000, alpha=0.05) -> (lo, hi)`; `paired_significance(scores_a, scores_b) -> p_value` (via `scipy.stats.wilcoxon`, questions as the paired unit).
- **Validation checks:** CI width shrinks as sample size grows; CI on identical repeated scores collapses to a point; known synthetic A>B case yields p < 0.05; seeded RNG makes bootstrap reproducible.
- **How I verify it worked:** `pytest tests/test_bootstrap.py -v`; re-run with the same seed twice and diff CI output for exact reproducibility.
- **Git commit:** `T3.3: bootstrap CI + paired significance testing`
- **Mid-progress report use:** infrastructure — every headline table in the report needs this (retrieval metrics + CIs table).
